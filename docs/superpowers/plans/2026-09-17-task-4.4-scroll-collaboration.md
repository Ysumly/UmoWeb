# Task 4.4 滚动协同与本地工具入口实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复公开文章目录与 Markdown 编辑分栏的滚动体验，并建立与“游戏”同级的“工具”入口和 `/tools` 工具中心。

**Architecture:** 公开文章侧栏由 CSS sticky 与少量 `ResizeObserver` 状态组成，内容超过半屏时降级为现有抽屉。Markdown 编辑器通过共享纯函数和 composable 双向按比例同步滚动，并通过统一 CSS 高度模型保证左右面板等高。公开导航抽成共享目录，工具中心复用页面聚合模式但不复刻游戏业务组件。

**Tech Stack:** Vue 3.5、Vite 8、Node test、Playwright 1.63、原生 `ResizeObserver`、`matchMedia`、`requestAnimationFrame`。

**Spec:** 本计划由 2026-09-17 用户批准并补充的 Task 4.4 范围直接定义，当前无独立设计稿。

## Global Constraints

- 不修改后端 API、数据库、Markdown 存储格式、JWT、认证或现有编辑器草稿键。
- 不引入滚动同步、编辑器或图标依赖。
- 目录和 drawer 的最大高度不得超过 `50vh`；窄屏 `<=980px` 继续使用抽屉。
- 编辑器双向同步按可滚动比例计算，移动端单面板不启用同步。
- `/tools` 与 `/editor` 使用公开端布局；`/editor` 继续只保存浏览器本地草稿。
- 工具中心当前只包含 Markdown 编辑器，目录结构允许后续扩展，但本期不新增其他工具。
- 文档、测试和视觉基线与代码同批维护，不把计划能力写成已实现能力。

- [x] **Step 3: 实现纯函数**

以 `maxScroll = Math.max(0, scrollHeight - clientHeight)` 为基准。比例和结果均夹在 `0..1` 或 `0..maxScroll` 内。

- [x] **Step 4: 实现 composable**

`useSyncedScroll` 使用两条 `scroll` 监听和一个“下一次目标事件由同步产生”的标记，防止 A 驱动 B 后再反向驱动 A。每个方向通过 `requestAnimationFrame` 合并连续事件。

使用 `matchMedia`：

- `EditorPage.vue`: `(min-width: 981px)`
- `ContentEditPage.vue`: `(min-width: 701px)`
- `OptionPage.vue`: About 和 Project 各调用一次 `(min-width: 701px)`

媒体查询不匹配或任一元素不可滚动时直接返回。组件卸载和媒体查询变化时移除监听。

- [x] **Step 5: 统一编辑工作区 CSS**

在 `style.css`：

1. `.editor-workspace`、`.admin-editor-workspace` 使用固定 `height: clamp(520px, 68vh, 720px)`。
2. `.admin-option-workspace` 使用 `height: clamp(420px, 60vh, 620px)`。
3. `.admin-editor-pane` 改为 flex column、`min-height: 0` 和 `overflow: hidden`。
4. 输入 textarea 使用 `flex: 1`、`min-height: 0` 和 `height: 100%`，不再依赖固定 `620px`。
5. 预览面板移除独立 `max-height`，改为各自 `overflow: auto`。
6. `<=700px` 时工作区使用 `min(70vh, 620px)` 或工具页对应高度，活动面板改为 `display: flex`，非活动面板继续隐藏。

- [x] **Step 6: 增加浏览器回归**

在 `editor.spec.js` 和 `admin.spec.js` 中断言：

1. 输入面板、textarea 和预览面板底部偏差不超过 `1px`。
2. textarea 滚到 `40%` 后，预览滚动比例误差不超过 `2%`。
3. 预览滚到 `20%` 后，textarea 比例误差不超过 `2%`。
4. 等待两个 animation frame 后滚动位置稳定，没有来回抖动。
5. `390px` 移动端只显示活动面板，不执行双面板同步。
6. 管理端图片、About 和 Project 的既有功能测试继续通过。

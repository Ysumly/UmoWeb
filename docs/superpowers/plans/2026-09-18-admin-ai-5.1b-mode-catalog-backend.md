# 5.1B 管理端 AI 模式目录后端 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付数据库持久化、提示词版本化、可复制、可启停、可排序和可回滚的 AI 转换模式管理后端。

**Architecture:** `ai_transform_modes` 保存模式元数据和当前版本号，
`ai_transform_mode_versions` 保存不可变提示词版本。管理端 Service 在事务内创建模式或新版本，
并只保留最近 10 版。Controller 只返回 VO，模式运行时配置通过独立 Service 暴露给 5.1D。

**Tech Stack:** Spring Boot 4.1、Java 17、MyBatis 4.0.1、MySQL 8.4、JUnit 5、Mockito、MockMvc。

**Spec:** [管理端 AI 计划总索引](2026-09-18-admin-ai-index.md) 与
[5.1A 产品与数据契约](2026-09-18-admin-ai-5.1a-product-contract.md)

## Global Constraints

- 默认模式提示词只存在 `schema.sql`、`seed-data.sql` 和幂等迁移 SQL 中。
- 正常响应直接返回 VO 或数组；异常继续使用 `{ code, message }`。
- 新建、复制、更新和回滚成功返回 HTTP 200；不返回 201。
- `modeKey` 唯一、创建后不可修改，格式为 `[A-Z][A-Z0-9_]{2,63}`。
- 系统提示词长度 1–20,000，说明最多 500，名称最多 100。
- 每次提示词或校验策略变化都生成新版本；每个模式只保留最近 10 版。
- 回滚复制历史版本生成新版本，不修改或删除历史记录。
- 首版不提供永久删除；下线模式只能设置为停用。

```sql
CREATE TABLE IF NOT EXISTS ai_transform_modes (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    mode_key VARCHAR(64) NOT NULL UNIQUE,
    name VARCHAR(100) NOT NULL,
    description VARCHAR(500) NOT NULL DEFAULT '',

    updated_at DATETIME NOT NULL DEFAULT NOW() ON UPDATE NOW(),

CREATE TABLE IF NOT EXISTS ai_transform_mode_versions (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    mode_id BIGINT NOT NULL,
    version_no INT NOT NULL,
    system_prompt MEDIUMTEXT NOT NULL,
    validation_profile VARCHAR(32) NOT NULL,
    created_at DATETIME NOT NULL DEFAULT NOW(),
    UNIQUE KEY uk_ai_mode_version (mode_id, version_no),
    CONSTRAINT fk_ai_mode_version_mode
        FOREIGN KEY (mode_id) REFERENCES ai_transform_modes(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

- [ ] **Step 2: 实现事务内创建与复制**

`create()` 在单事务中插入 mode 和 version 1，默认 `enabled=false`，重复 `modeKey` 返回 409。
`copy()` 只复制当前版本提示词、校验策略和说明，名称和 `modeKey` 使用请求值，新模式始终停用。

- [ ] **Step 3: 实现乐观更新**

`update()` 先读取当前 mode。`expectedVersion` 不一致返回 409。只有提示词或校验策略变化时，
才插入 `currentVersion + 1` 并通过条件更新推进版本；名称、说明、启停和排序变化不产生提示词版本。

- [ ] **Step 4: 实现 10 版保留与回滚**

插入新版本后删除 `version_no < currentVersion - 9` 的记录。回滚读取目标历史版本，
复制为新版本，版本号继续递增，并更新 version 1 的时间不改变。

- [ ] **Step 5: 添加并发测试**

两个 update 使用相同 `expectedVersion` 时，只允许第一个成功，第二个返回 409；
数据库中不存在跳号或两个相同 `currentVersion`。

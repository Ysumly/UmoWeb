# Task 3.4 全文搜索实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让公开搜索覆盖标题、摘要和 Markdown 正文，并为正文命中返回可理解摘要。

**Architecture:** 使用 MySQL 8.4 `content_search` 表和 `FULLTEXT ... WITH PARSER ngram` 索引正文；文章发布和更新时在同一事务内同步索引，撤回或删除时移除索引；独立回填入口读取 `body_path` 重建全部已发布正文索引。公开查询只返回 `PUBLISHED`，标题/摘要继续支持子串匹配，正文使用全文相关度并生成纯文本摘要。

**Tech Stack:** MySQL 8.4、Spring Boot 4.1、MyBatis 4.0.1、Java 17、Vue 3、Playwright 1.63

**Spec:** `docs/superpowers/plans/2026-09-12-four-phase-roadmap.md` 的 Task 3.4

## Global Constraints

- 正常响应不增加统一包装；错误继续返回 `{ code, message }`。
- 公开搜索只返回 `PUBLISHED`，不得泄露草稿标题、摘要或正文。
- 正文索引不写入现有 `contents` 表，不引入外部搜索服务或新基础设施。
- 回填必须可重复执行，缺失正文文件时保留标题/摘要搜索并记录正文索引缺失。
- 搜索参数继续限制为 200 字符，既有同 IP 10 秒 1 次限流保持生效。
- Schema、接口、查询语义、CI、测试基线和审计文档必须同步更新。

- [ ] **Step 3: 创建迁移和 Mapper**

迁移表包含 `content_id BIGINT PRIMARY KEY`、`body_text LONGTEXT NOT NULL`、
`updated_at DATETIME`、外键级联删除和 `FULLTEXT KEY ft_content_search_body (body_text) WITH PARSER ngram`。
Mapper 使用 `INSERT ... ON DUPLICATE KEY UPDATE`，删除条件为内容不存在或状态不是 `PUBLISHED`。

- [ ] **Step 4: 实现索引服务和回填入口**

继续，再删除所有非发布索引行。`--app.search.backfill-only=true` 且非 Web 模式时，启动 Runner 执行一次回填后退出。

- [ ] **Step 5: 增加回填脚本并验证**

`--spring.main.web-application-type=none --app.search.backfill-only=true`。连续执行两次后索引数与已发布内容数一致。

# 5.1F 管理端 AI 质量与发布 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用假供应商完成可重复自动化验收，用固定样本完成五种模式的受控真实模型质量评估，
收口全部文档，并在不影响现有站点的前提下完成可关闭的生产发布。

**Architecture:** CI 启动无第三方依赖的 OpenAI-compatible 假服务，后端指向该地址，
接口冒烟覆盖模式管理和转换契约。真实 DeepSeek 只通过本地评测脚本手动调用，结果保存在被忽略的
`Downloads/` 目录。生产默认关闭 AI，验收通过后再由服务器侧环境变量启用。

**Tech Stack:** Python 标准库 HTTP Server、PowerShell、Bash、Spring Boot 集成、Playwright、
GitHub Actions、Docker Compose、阿里云 Workbench CLI。

**Spec:** [管理端 AI 计划总索引](2026-09-18-admin-ai-index.md) 与 5.1A–5.1E 子计划。

## Global Constraints

- CI 不得读取或调用真实 DeepSeek，不得使用 `DEEPSEEK_API_KEY`。
- 假服务只回显 user content，并返回固定 usage；它只验证协议和保真校验，不伪装成质量评估。
- 真实模型评测只在本地或受控服务器手工执行，输入使用仓库内合成的公开安全样本。
- 真实评测结果、token 消耗和人工评分写入 `Downloads/ai-evaluations/`，不进入版本库。
- AI 默认关闭；关闭时文章编辑器、发布、搜索和公开端行为必须与 5.1D 之前一致。
- 发布失败时优先设置 `APP_AI_ENABLED=false` 重启后端；不回滚数据库中的模式和提示词记录。
- Linux 视觉基线必须通过手动工作流生成 artifact、人工审查后再提交，不能复制 Windows 快照。
- 只有所有自动测试、受控评测和文档检查通过后，才允许把索引全部标记完成。

- [ ] **Step 1: 在 Python 冒烟脚本增加模式管理场景**

流程固定为：

1. `GET /api/admin/ai/modes` 确认五个默认模式。
2. 创建 `CI_AI_MODE_<uuid>`，提示词为 `你是测试转换器。`，校验策略 `NONE`。
3. 修改提示词，断言版本从 1 变为 2。
4. 使用相同 expectedVersion 再次修改，断言 409。
5. 复制模式，断言新模式停用。
6. 查询版本并回滚到版本 1，断言生成版本 3。
7. 启用复制模式或测试模式，调用转换接口，断言返回 `modeVersion` 和 usage。
8. 停用测试模式，调用转换接口返回 409。

- [ ] **Step 2: 在 PowerShell 冒烟脚本增加同一场景**

脚本必须使用相同请求、断言和成功/失败输出，失败时打印请求 ID，不打印正文和提示词。
由于首版没有永久删除，CI 数据库是一次性的；脚本不得尝试删除模式。

- [ ] **Step 3: 增加假 Provider 断言**

### Task 3: 建立五种模式的固定质量样本

**Files:**
- Create: `scripts/ai/evaluation/cases.json`

- Create: `scripts/ai/evaluation/test_cases.py`

**Interfaces:**

```json
      "source": "Markdown 原文",
      "criteria": ["非标题正文完全一致", "代码块和链接不变"]
    }
  ]
}
```

- [ ] **Step 1: 为每个模式写两个公开安全样本**

样本总计 10 个：

| 模式 | 样本一 | 样本二 |
|---|---|---|
| `STRUCTURE_CLEANUP` | 含 H2、列表、代码块的技术笔记 | 含引用、表格和链接的说明文 |
| `MODERN_TO_CLASSICAL` | 现代叙事段落 | 含数字和专有名词的说明段 |
| `ENGLISH_TO_CHINESE` | 英文技术说明 | 英文叙事段落 |
| `CHINESE_TO_ENGLISH` | 中文技术说明 | 中文叙事段落 |
| `LIGHT_NOVELIZATION` | 短叙事片段 | 场景描写片段 |

每个样本必须少于 2,000 字符，不包含个人隐私、真实服务器地址、密钥或未经授权的第三方长文。

- [ ] **Step 2: 写人工评分口径**

README 固定评分：

```text
5：完全满足模式要求，无事实问题
4：有轻微风格或措辞问题，事实和结构完整
3：可理解但存在明显遗漏、语气偏差或结构变化
2：关键信息丢失或表达不可用
1：完全失败、空结果或违反模式边界
```

结构整理必须通过自动和非标题正文 100% 一致检查。其他模式每个样本至少 4 分，
翻译样本的数字、专有名词、链接和代码必须无误，小说化不得超出原文 1.5 倍。

- [ ] **Step 3: 校验样本清单**

编写一个小型 Python `unittest` 检查：

- 10 个唯一 `id`。
- 五种模式各两个样本。
- 所有 `source` 非空。
- 不含 `http://`、`https://` 以外的外部地址中疑似敏感信息。
- JSON 能被标准库解析。

```bash

git commit -m "test: add ai mode quality cases"
```

### Task 4: 实现受控真实模型评测脚本

**Files:**
- Create: `scripts/ai/evaluate-ai-modes.ps1`
- Create: `scripts/ai/tests/evaluate-ai-modes-test.ps1`
- Modify: `.gitignore`

**Interfaces:**

```powershell
.\scripts\ai\evaluate-ai-modes.ps1 `
  -BaseUrl "http://127.0.0.1:8080" `
  -Username "admin" `
  -Password "<current-password>" `
  -OutputDirectory "Downloads\ai-evaluations\20260918T120000" `
  -MaxCalls 5 `
  -Modes STRUCTURE_CLEANUP,MODERN_TO_CLASSICAL,ENGLISH_TO_CHINESE,CHINESE_TO_ENGLISH,LIGHT_NOVELIZATION
```

- [ ] **Step 1: 写脚本测试**

使用本地 mock HTTP Server 返回登录、能力、模式和转换响应，断言：

- 密码不会打印。
- 每个样本调用一次转换。
- 输出目录包含 `results.json` 和 `review.md`。
- 任一请求失败时脚本退出非零，但已完成的样本保存在输出目录。
- 429 时停止后续调用，避免持续消耗预算。

- [ ] **Step 2: 实现评测脚本**

- 登录获取 token，只保存在当前进程内存。
- 读取 `cases.json`，按模式分组。
- 调用 `GET /api/admin/ai/capabilities`，跳过未启用的模式并明确记录。
- 调用 `POST /api/admin/ai/transform`，保存 requestId、modeVersion、model、usage、
  耗时、输出和客观长度。
- 不自动写文章接口。
- 输出目录不存在时创建；写入机器可读 `results.json` 和人工阅读 `review.md`。
- 单次默认最多调用 5 次，避免与后端 10 分钟最多 5 次限流冲突；再次运行同一输出目录时
  跳过已成功案例，429 保存已有进度后以非零状态退出。
- 脚本结束打印总 token、总调用数、失败数和输出目录，不打印正文。

- [ ] **Step 3: 忽略评测结果**

在 `.gitignore` 加入：

```text

```

确认 `Downloads/` 已整体忽略时仍保留该显式规则，防止路径移动后误提交。

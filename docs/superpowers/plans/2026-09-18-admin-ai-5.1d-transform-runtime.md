# 5.1D 管理端 AI 转换运行时 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付供应商无关、受管理员认证保护的 AI 转换运行时，包括能力查询、DeepSeek 适配、
请求限制、超时、结果校验、错误归一化和脱敏日志。

**Architecture:** Controller 只负责 HTTP 契约，`AiTransformService` 从模式目录读取当前版本，
通过 `AiTransformProvider` 调用模型并对结果执行策略校验。DeepSeek 使用 OpenAI-compatible
`/chat/completions`，业务层不依赖 DeepSeek 类型。请求限流、并发控制和配置校验独立实现。

**Tech Stack:** Spring Boot 4.1、Java 17、Spring `RestClient`、MyBatis 4.0.1、Mockito、
MockMvc、MockRestServiceServer、JUnit 5。

**Spec:** [管理端 AI 计划总索引](2026-09-18-admin-ai-index.md) 与
[5.1B 模式目录后端](2026-09-18-admin-ai-5.1b-mode-catalog-backend.md)

## Global Constraints

- `GET /api/admin/ai/settings`、`GET /api/admin/ai/capabilities` 和
  `POST /api/admin/ai/transform` 由本计划交付；模式 CRUD 已由 5.1B 交付。
- 正常响应直接返回 VO，错误继续使用 `{ code, message }`。
- 供应商和模型全局配置，模式不得覆盖模型。
- 单次输入最多 20,000 字符，输出最多 60,000 字符，超时 180 秒，
  10 分钟最多 5 次，同时最多一个请求。
- 不使用费用硬上限，但记录 token 和耗时；不得把正文、结果、提示词或 API Key 写日志。
- 真实 DeepSeek 调用不进入 CI；单元测试使用假供应商或 Mock HTTP Server。
- Spring AI OpenAI Starter 目前没有业务调用；本计划改用供应商无关接口后移除该依赖和
  `spring.ai.openai` 配置，防止出现第二套未使用配置。

- [ ] **Step 1: 写四个策略的失败测试**

- `EXACT_CONTENT`：移除 Markdown ATX 标题行后，非标题文本归一化必须完全一致。
- `TRANSLATION`：结果非空、长度合规、围栏代码块数量和链接数量与原文一致。
- `LIGHT_EXPANSION`：结果长度为原文的 1–1.5 倍，围栏代码块和链接数量不得增加。
- `NONE`：结果非空且不超过最大字符数。

示例：

```java
assertThatThrownBy(() -> validator.validate(
        AiValidationProfile.EXACT_CONTENT,
        "原文段落",
        "被改写的段落",
        60000))
        .isInstanceOf(BusinessException.class)
        .hasMessageContaining("结构整理改变了正文");
```

- [ ] **Step 2: 实现校验器**

使用标准 Java 字符串处理，不新增 Markdown 解析依赖。校验失败统一返回 502，
失败结果不得覆盖已有前端结果。

- [ ] **Step 3: 固定边界**

空结果、仅空白、输出超长、围栏数量变化和链接数量变化均失败。`EXACT_CONTENT` 允许增加标题、
调整标题层级和段落顺序之外的空行，但不能改变任意非标题字符序列。

## Verification

- 默认 `APP_AI_ENABLED=false` 时应用可启动，能力接口返回禁用。
- 启用后缺少 `DEEPSEEK_API_KEY` 或 `DEEPSEEK_MODEL` 会阻止启动。
- Provider 请求始终使用 system message 和独立 user message，不把正文拼接进系统提示词。
- 10 分钟内第六次请求和并发第二个请求分别返回 429，异常路径会释放 lease。
- 所有 Provider 和校验错误映射为冻结状态码，且日志不包含正文、结果、提示词或密钥。
- `mvn test`、敏感信息扫描和 diff 检查通过。

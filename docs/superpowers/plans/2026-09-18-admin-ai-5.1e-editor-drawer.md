# 5.1E 文章编辑器 AI 抽屉 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development`
> (recommended) or `superpowers:executing-plans` to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在管理端文章编辑器提供可关闭、可缩成浮动窗的 AI 转换抽屉，支持正文带入、模式选择、
执行、取消、结果编辑和复制，同时严格保证结果不自动写入文章。

**Architecture:** `AiTransformDrawer.vue` 只负责抽屉状态和交互，纯规则放在
`utils/aiDrawer.js`。`ContentEditPage.vue` 提供当前 Markdown 正文和打开入口，不参与结果合并。
草稿使用 `sessionStorage`，结果使用 `localStorage`，网络请求通过现有 Axios client 和
`AbortController`。

**Tech Stack:** Vue 3.5、Axios 1.18、Vite 8、Node test、Playwright 1.63。

**Spec:** [管理端 AI 计划总索引](2026-09-18-admin-ai-index.md) 与
[5.1D 转换运行时](2026-09-18-admin-ai-5.1d-transform-runtime.md)

## Global Constraints

- 不新增前端依赖，不引入第三方抽屉、编辑器、图标或剪贴板库。
- 抽屉仅在 `/api/admin/ai/capabilities.enabled=true` 时显示入口。
- 带入正文必须由用户点击触发，不随页面加载自动读取或发送。
- 单次正文最多 20,000 字符；超出时前端阻止提交并显示计数。
- 结果只能编辑、复制和重新转换，不得插入、替换、保存或发布文章。
- 源草稿键固定为 `umo-admin-ai-source-v1`，结果键固定为 `umo-admin-ai-result-v1`。
- 取消只中止当前浏览器请求和等待，不承诺供应商停止计费；界面必须明确说明。
- 关闭抽屉、页面刷新或离开编辑器时不得丢失未保存表单提示或阻塞现有文章保存逻辑。

- [ ] **Step 1: 实现抽屉基础结构**

抽屉包含：

- 标题栏：模式、关闭按钮、缩成浮动窗按钮。
- 源草稿区：可编辑 textarea、字符计数、“带入当前正文”按钮。
- 模式区：从 `capabilities.modes` 选择 `modeKey`。
- 执行区：第三方处理提示、执行按钮、取消按钮和状态文本。
- 结果区：Markdown 源码 textarea、只读预览、复制、重新转换按钮。

不显示功能说明式营销文案，只显示操作所需的状态、限制和隐私提示。

- [ ] **Step 2: 实现带入正文**

点击“带入当前正文”时将 `currentSource` 写入源 textarea 和 `sourceState`。
如果 textarea 已有不同内容，先使用 `window.confirm` 确认替换。

- [ ] **Step 3: 实现本地恢复**

组件挂载时读取 session 源草稿和 local 结果。恢复成功后显示“已恢复本地草稿/结果”；
恢复失败时删除坏记录并保持空白。`sessionStorage` 或 `localStorage` 抛错时显示
“本地保存不可用”，但允许继续当前会话内编辑。

- [ ] **Step 4: 实现浮动模式**

点击缩成小窗后显示固定浮动按钮，按钮含模式名和“恢复”文本。浮动状态下继续显示执行中状态；
恢复时保持源、结果和滚动位置。`390px` 下浮动按钮不得遮挡页面主要操作。

- [ ] **Step 5: 实现可访问性**

- 抽屉使用 `role="dialog"` 和 `aria-modal="true"`。
- 打开后焦点进入模式选择或源输入。
- Escape 在没有请求时关闭抽屉；请求中先提示取消。
- 关闭后焦点返回文章页打开按钮。
- 所有 textarea 有明确 `aria-label`。

- [ ] **Step 6: 增加响应式样式**

桌面抽屉宽度 `min(720px, 48vw)`，固定在右侧，最大高度 `calc(100vh - 24px)`。
`980px` 以下改为全屏面板；结果和源码在窄屏使用上下布局。全页面不得出现横向滚动。

### Task 3: 实现执行、取消、结果编辑和覆盖确认

**Files:**

**Interfaces:**
- Consumes: `transformAiContent` 与 `AbortController`。
- Produces: 结果状态 `{ modeKey, modeVersion, originalContent, content, usage, updatedAt }`。

- [ ] **Step 1: 写覆盖规则测试**

增加以下断言：

```javascript
assert.equal(shouldConfirmResultOverwrite(null), false)
assert.equal(shouldConfirmResultOverwrite({
  originalContent: 'A', content: 'A',
}), false)
assert.equal(shouldConfirmResultOverwrite({
  originalContent: 'A', content: 'B',
}), true)
```

- [ ] **Step 2: 实现执行**

执行前再次使用 `validateAiSource`。设置 `inFlight=true`，创建新的 `AbortController`，
调用 `transformAiContent({ modeKey, content }, { signal })`。同一抽屉不得重复提交。

成功后使用响应字段建立结果状态，`originalContent` 和 `content` 均设为服务端结果，
并将结果写入 `localStorage`。

- [ ] **Step 3: 实现重新转换**

已有结果被手动编辑时先确认。确认后保留源草稿，重新执行当前模式；失败或取消不得覆盖旧结果。

- [ ] **Step 4: 实现取消**

点击取消调用 `abortController.abort()`，状态改为“已取消，已有结果未改变”。后端可能已经计费的说明
在请求期间持续可见。

- [ ] **Step 5: 实现复制**

优先使用 `navigator.clipboard.writeText`，失败时使用临时 textarea 和
`document.execCommand('copy')`，两者都失败时提示手动选择复制。复制成功不改变文章表单。

- [ ] **Step 6: 映射请求错误**

- 429：显示限流提示，不自动重试。
- 502：显示结果不符合保真要求或供应商返回无效结果。
- 503：显示 AI 当前不可用，文章编辑不受影响。
- 504：显示超时，可手动重试。
- 其他错误使用 `getApiErrorMessage`，并在消息前附请求 ID（若响应提供）。

### Task 4: 接入文章编辑器

**Files:**
- Modify: `Client Side/umo-web-frontend/src/views/admin/ContentEditPage.vue`

**Interfaces:**
- Consumes: `getAiCapabilities` 和 `AiTransformDrawer`。
- Produces: 当前 `form.body` 作为只读 `currentSource` 传给抽屉。

- [ ] **Step 1: 加载能力**

页面挂载时调用 `getAiCapabilities()`。失败或 `enabled=false` 时不显示 AI 按钮，不写入全局错误；
AI 不可用不能影响文章编辑器其他功能。

- [ ] **Step 2: 增加入口**

在 Markdown 正文工具区增加“AI 转换”按钮，打开抽屉。按钮与图片上传、导入等现有操作同级。
打开抽屉前不自动携带正文；用户必须点击“带入当前正文”。

- [ ] **Step 3: 传递当前正文**

`currentSource` 使用 `form.body || ''`。抽屉打开后文章正文变化时，已带入的源草稿保持不变；
用户再次点击“带入当前正文”时才用确认流程刷新。

- [ ] **Step 4: 保持文章脏状态独立**

AI 草稿和结果不得设置文章表单的 `dirty` 状态，不得调用 `handleSubmit`、路由跳转或图片上传。
关闭抽屉不得清空或修改 `form.body`。

- [ ] **Step 5: 处理离开和页面隐藏**

现有文章编辑器离开保护保持不变。抽屉额外监听 `beforeunload`：请求中或源草稿有未保存变化时
提示可能丢失。源草稿已写入 sessionStorage 时刷新后可恢复，但关闭标签页后不保证保留。

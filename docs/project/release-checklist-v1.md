只有全部阻断项通过并由 `release-owner` 明确批准后，才允许切换正式流量。

## 1. 发布范围

### 1.1 公开端

首批正式发布包含以下八个公开路由：

| 路由 | 能力 |
|---|---|
| `/` | 首页、站点信息和最新已发布内容 |
| `/library` | 已发布内容列表、类型/分类/标签筛选、分页 |
| `/search` | 基于标题和摘要的已发布内容搜索，保留 10 秒限流 |
| `/post/:slug` | 已发布 Markdown 详情和前后文章导航 |
| `/about` | About 页面配置 |
| `/project` | Project 页面配置 |
| `/editor` | 纯浏览器 Markdown 导入、编辑、预览、下载和本地草稿 |
| `/privacy` | 访问日志目的、最小字段、实际保留期和管理员访问边界 |
| `/games` | 四款训练游戏入口、统一导航和本地成绩说明 |
| `/games/stroop`、`/games/digit-span`、`/games/poker-memory`、`/games/schulte` | 四款训练游戏规则、成绩和响应式交互 |

公开 404 回退、亮暗主题、响应式布局和 Markdown 安全渲染属于上述页面的交付条件。

### 1.2 管理端

首批正式发布包含以下六个管理业务页：

| 页面 | 能力 |
|---|---|
| 登录 | 单管理员登录和受保护路由 |
| 文章 | 列表、新建、编辑、发布/撤回和删除 |
| 分类 | 列表、新建、编辑和受保护删除 |
| 标签 | 列表、新建、编辑和受保护删除 |
| 图片 | 列表、引用/未引用筛选和受保护删除 |
| 站点设置 | 站点标题、副标题、About 和 Project 配置 |
| 修改密码 | 凭据轮换和旧 JWT 立即失效 |

图片上传属于文章编辑能力，保持现有 MIME、文件签名和 50MB 限制；新建文章支持单文件
Markdown 导入和 YAML front matter 回退。

### 1.3 接口基线

公开端 8 个接口、管理端 21 个接口、总计 29 个接口。接口路径、请求字段、响应结构、状态码和
查询语义以当前 Controller、Mapper XML 和 `api-reference.md` 为准。

### 1.4 明确排除

以下能力不进入 v1 正式发布范围：

- 第三方广告或外部访问统计；自托管六字段安全日志不属于排除项。
- 长期镜像仓库和远程自动发布服务；第二阶段采用开发机版本归档、Workbench 传输和 ECS 本地发布/回滚流程。
- 多实例部署和共享限流。
- 多管理员、注册和 RBAC。
- AI 业务接入。
- 搜索引擎收录优化；当前 `noindex` 行为保持不变。

后续若要加入上述任一能力，必须新增修订记录，重新确认发布风险，并重新验收受影响的阻断项。

## 2. 发布职责

真实姓名和联系方式只保存在仓库外的发布台账中。职责允许由同一人兼任，但下列检查项必须分别
指定唯一最终责任人。

| 职责标识 | 责任 |
|---|---|
| `release-owner` | 冻结范围、批准发布或回滚、接受或拒绝例外 |
| `platform-operator` | 服务器、镜像、域名、HTTPS、代理、健康检查和回滚操作 |
| `data-verifier` | 数据库与文件备份、隔离恢复、数据一致性校验 |
| `acceptance-owner` | 面向用户的功能、接口和发布证据验收 |

## 3. 阻断级别

- `P0`：安全、数据完整性或不可恢复风险。任何一项失败都禁止发布，不允许例外。
- `P1`：功能或运维验收风险。默认禁止发布；只有 `release-owner` 在仓库外发布台账记录
  明确期限、缓解措施和回滚责任后才可临时接受。

## 5. 回滚触发条件

出现以下任一情况时立即执行回滚：

- 检测到数据丢失、数据损坏、数据库与 Markdown/图片不一致。
- 未发布内容、管理员资料或请求凭据泄露。
- 出现未授权管理访问或可复现的认证绕过。
- 管理员密码、数据库密码或 JWT secret 泄露。

出现以下任一情况时，经一次记录在案的修复尝试后仍不可用，执行回滚：

- 首页、公开 API 或管理员登录不可用。
- HTTPS、跳转、静态资源或核心 API 返回错误。
- 正式环境接口冒烟无法恢复到 29/29。

REL-01 至 REL-14 中除上述即时回滚项外的阻断项，在 30 分钟内无法修复时执行回滚。
回滚后必须停止继续发布，重新由 `release-owner` 判断是否允许再次尝试。

## 6. 发布记录

正式发布结果不写入仓库，只记录在服务器侧发布台账中。每条记录至少包含：

| 记录项 | 要求 |
|---|---|
| 候选版本 | Git commit、前后端镜像标签、image ID 和归档 SHA-256 |
| 批准记录 | `release-owner`、批准时间和发布范围 |
| 数据证据 | 备份 SHA-256、恢复时间、行数、Markdown 文件数和图片文件数 |
| 安全证据 | 凭据轮换时间、DNS 归属职责、证书续期职责、证书到期时间和真实客户端 IP 校验结果 |
| 验收证据 | 29/29 冒烟结果、核心页面结果和失败项处置 |
| 例外记录 | 级别、责任人、期限、缓解措施和回滚责任 |
| 发布结果 | 发布时间、最终 digest、健康状态和回滚判断 |
